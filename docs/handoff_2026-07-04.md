## Recent Fix: Staff Edit Error

User reported a staff edit failure:

```text
column "normalized_store" can only be updated to DEFAULT
```

Root cause:

- `profiles.normalized_store` is a generated DB column:
  `generated always as (public.normalize_store_name(store)) stored`
- Edge Function `auth-policy` was directly updating `normalized_store`.

Fix applied:

- Removed `normalized_store: storeName` from `supabase/functions/auth-policy/index.ts`.
- Deployed only Supabase Edge Function:

```bash
supabase functions deploy auth-policy
```

No app rebuild was required.

Commit:

- `0e231de fix: avoid updating generated profile store column`

## Build and Release Procedure

For Windows/Android releases:

1. Bump version in `pubspec.yaml`.
2. Bump Inno installer version if needed.
3. Format Dart files only.
4. Run:

```bash
flutter analyze
flutter test
git diff --check
```

5. Commit selected files only.
6. Tag and push:

```bash
git tag vX.Y.Z
git push origin main --tags
```

7. Wait for GitHub Actions:
   - `.github/workflows/windows-release.yml`
   - `.github/workflows/android-release.yml`
8. Download artifacts.
9. Create/update GitHub release.
10. Update Supabase `app_updates`.

Do not commit local/generated files listed at the top unless explicitly asked.

## No-Compile Patch Strategy

No app rebuild needed for:

- Supabase Edge Function changes
- DB migrations/policies/triggers
- Server-side validation/permissions
- Remote config rows such as `app_updates`

App rebuild needed for:

- Flutter UI layout changes
- Dart client-side logic changes
- Assets/fonts/native plugin changes
- Inno installer behavior changes

Potential future option:

- Shorebird Code Push can patch Dart code over the air, including Windows support according to its docs.
- It requires one new Shorebird-based release first.
- It cannot patch native code, assets, Flutter engine changes, or native dependency changes.
